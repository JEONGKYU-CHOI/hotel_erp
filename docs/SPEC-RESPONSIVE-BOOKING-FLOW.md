# 스펙: 반응형 UI·예약 흐름 단순화·입력 검증·지도 연동

- 상태: Approved | 2026-08-05

## 목표

부킹엔진과 PMS를 모바일·태블릿·데스크톱에서 안정적으로 사용할 수 있게 하고, 예약 진입 단계를 줄이면서 회원 상태에 맞는 예약자 정보와 신뢰할 수 있는 연락처 검증·위치 안내를 제공한다.

## 범위

- 반응형 기준을 모바일 `≤767px`, 태블릿 `768~1199px`, 데스크톱 `≥1200px`로 통일하고 부킹엔진 전체와 PMS `/admin`의 레이아웃·표·폼·모달을 정비한다.
- 부킹엔진 네비게이션은 데스크톱 전체 메뉴, 태블릿 축약 메뉴, 모바일 햄버거/드로어 메뉴로 제공하며 로그인·내 예약·언어 전환·예약 CTA에 접근할 수 있게 한다.
- 메인 예약 폼 제출 시 중간의 “00객실 가능합니다” 결과와 두 번째 클릭을 제거하고 `/book`으로 바로 이동해 가능 여부·요금제를 조회한다. 재고 HOLD는 최종 예약 제출 시에만 생성한다.
- 예약·결제 화면에 객실 이미지·객실명·요금제·투숙일·인원·박수·총액을 표시한다. 로그인 회원은 회원 프로필의 이름·전화·이메일을 사용해 예약자 입력을 숨기고, 비회원만 직접 입력한다.
- 회원가입·비회원 예약·결제 진입 시 이메일과 국내 휴대전화(`010`)를 프론트와 서버 양쪽에서 검증한다. 전화 검증·정규화는 공통 모듈로 분리해 추후 국가 선택+E.164 방식으로 교체 가능하게 한다.
- 위치 페이지의 가상 주소 `서울특별시 강남구 테헤란로 000 (역삼동)`는 강남역 인근 고정 좌표의 카카오맵 마커로 안내하고, 주소 복사·카카오맵 보기·길찾기 링크와 지도 로드 실패 대체 UI를 제공한다.

## 비목표

- 이번 작업에서 실제 호텔 주소·전화번호·운영 도메인을 확정하거나 해외 전화번호 입력 UI를 제공하지 않는다.
- PMS 기능 자체나 예약·결제 정책, DB 업로드 이미지, 기존 예약 데이터를 변경하지 않는다.
- Google Maps 동시 지원, 실시간 교통·주변 장소 검색, 카카오 개발자 계정 생성·운영 키 발급은 포함하지 않는다.

## 인수 기준

- GIVEN 모바일·태블릿·데스크톱 화면 WHEN 부킹엔진 주요 페이지와 PMS 주요 화면을 열면 THEN 가로 넘침이나 가려진 핵심 조작 없이 사용할 수 있다.
- WHEN 부킹엔진 네비게이션을 각 화면 폭에서 사용하면 THE SYSTEM SHALL 적절한 전체/축약/드로어 메뉴를 표시하고, 키보드·ESC·바깥 클릭으로 열고 닫을 수 있으며 현재 주요 링크와 예약 CTA를 유지한다.
- WHEN 메인 예약 폼에서 유효한 조건으로 예약하기를 누르면 THE SYSTEM SHALL 중간 가능 수량 결과 없이 `/book`으로 한 번에 이동해 객실 가능 여부와 요금을 표시한다.
- IF 선택 객실이 예약 불가이면 THEN THE SYSTEM SHALL HOLD를 만들지 않고 같은 화면에서 사유와 객실 조건 변경 경로를 제공한다.
- WHILE 회원이 로그인한 상태이면 THE SYSTEM SHALL 예약자 입력란을 숨기고 회원 프로필 정보를 예약에 사용한다. WHILE 비회원이면 THE SYSTEM SHALL 이름·전화·이메일 입력을 요구한다.
- IF 이메일 또는 국내 휴대전화 형식이 잘못되면 THEN THE SYSTEM SHALL 제출 전에 필드별 메시지를 표시하고, 직접 API 요청도 서버에서 거절한다.
- WHEN 예약 또는 결제를 검토하면 THE SYSTEM SHALL 선택 객실 이미지·명칭·요금제·일정·인원·박수·금액을 일관되게 표시한다.
- WHEN 위치 페이지를 열면 THE SYSTEM SHALL 가상 호텔 위치의 카카오맵과 외부 지도/길찾기 동작을 제공하고, 지도 로드 실패 시에도 주소와 대체 안내를 유지한다.

## 검증 방법

- 부킹엔진을 대표 폭 `390px`, `768px`, `1024px`, `1440px`에서 육안·키보드로 점검하고 네비게이션, 홈, 객실, 예약, 결제, 회원가입, 위치 페이지를 확인한다.
- PMS는 같은 대표 폭에서 로그인, 대시보드, 예약 목록·상세, 하우스키핑, 재고, 객실·요금 폼의 넘침과 조작 가능 여부를 확인한다.
- 회원/비회원 예약 성공, 예약 불가, 잘못된 이메일·전화번호, API 우회 입력을 자동 테스트하고 전체 백엔드 테스트와 프론트 프로덕션 빌드를 실행한다.
- Docker 8080 환경에서 기존 MySQL·업로드 볼륨을 유지한 채 최종 흐름과 업로드 객실 이미지 노출을 회귀 확인한다.

## 결정과 근거

- 국내 데모 호텔을 우선 완성하는 맥락에서 해외 전화까지 동시에 지원할 때 생기는 UI·검증 복잡성을 피하기 위해, 국제번호 입력을 바로 제공하는 대신 국내 `010` 검증을 공통 모듈로 구현하고 추후 E.164로 확장하기로 결정했다.
- 한국 내 가상 호텔의 위치 안내라는 맥락에서 국내 지도 경험과 초기 운영 부담을 고려해, 결제 계정이 필요한 Google Maps가 아니라 카카오맵과 고정 좌표를 사용하기로 결정했다.
- 예약 전환 과정에서 불필요한 두 번째 클릭을 없애되 재고의 불필요한 선점을 막기 위해, 메인에서 가능 수량 결과를 먼저 보여주는 방식이 아니라 `/book`에서 조회하고 최종 제출 시에만 HOLD를 생성하기로 결정했다.
- 여러 화면 크기에서 공통 품질을 확보하는 맥락에서 페이지별 임의 미디어쿼리를 늘리는 대신 세 구간의 공통 반응형 기준과 네비게이션 동작을 적용하기로 결정했다.
